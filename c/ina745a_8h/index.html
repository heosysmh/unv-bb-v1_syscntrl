    Detailed Description

    Concept: * The driver core is bus-agnostic: it only uses injected HAL callbacks (ina745a_i2c_write_f / ina745a_i2c_read_f), never a concrete I2C driver directly. This allows host-side unit testing with stubs (see tests/ina745a/) without any BSP/hardware dependency, exactly like the si5332 driver. * The HAL callbacks operate on whole logical registers (1/2/3/5 bytes), MSB first, matching the INA745x register map. Their signature is intentionally identical to drivers/i2c/i2cWrapper's i2c_writeRegMultipleBytes()/i2c_readRegMultipleBytes(), so they can be passed directly to ina745a_initialize() via a function-pointer cast - no adapter module needed (same pattern as si5332 with i2c_writeReg/i2c_readReg). The core itself never includes i2cWrapper.h or any BSP header.

    function ina745a_initialize

    Creates the device handle for instance devId (no I2C access).

    ina745a_t * ina745a_initialize (
    u32 devId,
    u8 i2c_addr,
    ina745a_i2c_write_f w,
    ina745a_i2c_read_f r,
    void * ctx
)

    Analogous to tpsm8286_initialize(): devId directly indexes the static instance pool (size INA745A_NUM_INSTANCES, defined in userDef.h), allowing multiple INA745A devices to be managed simultaneously.

    Parameters:

    • devId Instance index, 0 .. (INA745A_NUM_INSTANCES - 1).
    • i2c_addr 7-bit I2C address determined by the A0/A1 pin strapping on the board (datasheet Table 6-2), validated against INA745A_ADDR_MIN .. INA745A_ADDR_MAX.
    • w HAL register write callback, must not be NULL.
    • r HAL register read callback, must not be NULL.
    • ctx Opaque context pointer passed through to w and r.

    Returns:

    Pointer to the device handle, or NULL if devId or i2c_addr is out of range, or w/ r is NULL.
