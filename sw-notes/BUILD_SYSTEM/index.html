    Build System Documentation

    Overview

    The build system for the Efinix Sapphire SoC firmware supports multiple build configurations with different optimization levels and debug information.

    Build Configurations

    1. Debug Build (Default)

    Purpose: Development and debugging

    Compiler Flags: - -g3 - Maximum debug information (including macros) - -Og - Debug friendly optimization (better debuggability) - -march=rv32im_zicsr_zifencei - RISC-V ISA - -mabi=ilp32 - ABI - -DSMP - SMP support

    Output Directory: app/build/debug/

    Build Command:

    cd app
make debug

    VSCode Task: Build Debug (default build task, Ctrl+Shift+B)

    Output Files: - kria_sysCntrl.elf - ELF binary with debug symbols - kria_sysCntrl.hex - Intel HEX format - kria_sysCntrl.bin - Raw binary - kria_sysCntrl.asm - Disassembly - kria_sysCntrl.map - Linker map

    2. Release Build

    Purpose: Production firmware

    Compiler Flags: - -O3 - Maximum optimization (speed) - No debug information - -march=rv32im_zicsr_zifencei - RISC-V ISA - -mabi=ilp32 - ABI - -DSMP - SMP support

    Output Directory: app/build/release/

    Build Command:

    cd app
make release

    VSCode Task: Build Release

    Output Files: - kria_sysCntrl.elf - Optimized ELF binary - kria_sysCntrl.hex - Intel HEX format - kria_sysCntrl.bin - Raw binary - kria_sysCntrl.asm - Disassembly - kria_sysCntrl.map - Linker map

    3. Clean

    Purpose: Remove all build artifacts

    Build Command:

    cd app
make clean

    VSCode Task: Clean Project

    Removes: - app/build/debug/ - All debug build files - app/build/release/ - All release build files - app/build/ - Build directory (if empty)

    VSCode Integration

    Available Tasks

    1. Build Debug (Default, Ctrl+Shift+B)
    2. Creates debug build

    3. Output: build/debug/

    4. Build Release

    5. Creates release build

    6. Output: build/release/

    7. Clean Project

    9. Rebuild Debug

    Via Keyboard Shortcut: - Ctrl+Shift+B - Default build task (Debug)

    Via Command Palette: 1. Ctrl+Shift+P 2. Type "Tasks: Run Task" 3. Select desired task

    Via Terminal Menu: - Terminal → Run Task → Select task

    Build System Architecture

    Makefile Hierarchy

    app/makefile (Project-specific)
├── mcu/software/standalone/common/bsp.mk (BSP configuration)
├── mcu/software/standalone/common/riscv64-unknown-elf.mk (Compiler flags)
└── mcu/software/standalone/common/standalone.mk (Build rules)

    Important Variables

    Variable Debug Release Description
    DEBUG yes no Enable debug mode
    DEBUG_OG no - Optimization in debug mode
    BENCH no yes Benchmark optimization
    OBJDIR build/debug build/release Output directory

    Compiler Flag Logic

    Compiler flags are determined in riscv64-unknown-elf.mk:

    # Debug configuration
ifeq ($(DEBUG),yes)
    ifneq ($(DEBUG_OG),yes)
        CFLAGS += -g3 -O0    # Maximum debug, no optimization
    else
        CFLAGS += -g3 -Og    # Debug with minimal optimization
    endif
endif

# Release configuration
ifneq ($(DEBUG),yes)
    ifneq ($(BENCH),yes)
        CFLAGS += -Os        # Size optimization
    else
        CFLAGS += -O3        # Speed optimization
    endif
endif

    Configuration Comparison

    Property Debug Release
    Optimization Debug (-Og) Maximum (-O3)
    Debug Info Full (-g3) None
    Code Size Larger Smaller
    Execution Speed Slower Faster
    Debuggability Good Difficult
    Use Case Development Production

    Toolchain

    Compiler: riscv-none-elf-gcc

    Architecture: RISC-V 32-bit - ISA: rv32im_zicsr_zifencei - ABI: ilp32 - Extensions: M (Multiply/Divide), Zicsr (CSR), Zifencei (Fence)

    Linker Script: mcu/bsp/efinix/EfxSapphireSoc/linker/default.ld

    Tips & Best Practices

    Development

    • Use Debug builds for daily development
    • Debug builds enable better debugging with GDB/OpenOCD
    • Optimized should impact debugging much

    Testing

    • Test critical features with Release builds as well
    • Optimizations can reveal hidden bugs
    • Performance tests should be done with release builds

    Deployment

    • Use only Release builds for production
    • Smaller code size and better performance
    • Document the build configuration used

    Debugging

    • For hard-to-reproduce bugs: Compare debug and release builds
    • Use -O0 instead of -Og if debug build does not show locals of interrest: bash make debug DEBUG_OG=no

    Troubleshooting

    Problem: "make: command not found"

    Solution: Ensure GNU Make is installed

    sudo apt-get install build-essential

    Problem: "riscv-none-elf-gcc: command not found"

    Solution: RISC-V toolchain is not in PATH - Check toolchain installation - Set RISCV_BIN in environment or makefile

    Problem: Build artifacts not updating

    Solution: Perform a clean build

    make clean
make debug  # or make release

    Problem: Different behavior between debug and release

    Causes: - Uninitialized variables - Race conditions - Timing-dependent code - Undefined behavior

    Solution: Perform code review and static analysis

    Extensions

    Adding Additional Build Configuration

    Example: Size-optimized configuration

    1. Add to app/makefile:
    size:
    @echo "=== Building SIZE-OPTIMIZED configuration ==="
    @$(MAKE) -f $(firstword $(MAKEFILE_LIST)) build \
        DEBUG=no \
        BENCH=no \
        OBJDIR=build/size
    1. Add to .vscode/tasks.json:
    {
  "label": "Build Size-Optimized",
  "type": "shell",
  "command": "make",
  "args": ["size"],
  "options": {
    "cwd": "${workspaceFolder}/app"
  },
  "group": "build",
  "problemMatcher": ["$gcc"],
  "detail": "Build size-optimized firmware (-Os) → build/size/"
}
